§ 01 Motivación

¿Por qué migrar a SystemVerilog?

Verilog (1995/2001) fue diseñado para modelar circuitos digitales en simulación. SystemVerilog (2005, IEEE 1800) lo extiende con un sistema de tipos rico, construcciones para verificación, y bloques especializados que documentan intención.

Lo que ganás

  • Sistema de tipos más rico — enums tipados, structs, typedef.
  • Construcciones para verificación — assertions, coverage, randomización.
  • Interfaces, modports, packages — organización del código.
  • Bloques always_comb / always_ff / always_latch que documentan intención y atrapan bugs.

Lo que NO cambia

  • La sintaxis general — módulos, puertos, always, signals.
  • La semántica de simulación.
  • El comportamiento del hardware sintetizado.
  • La parametrización con parameter / localparam.
★ Idea clave

SystemVerilog es superset de Verilog. Tu código .v sigue compilando y podés mezclar .v con .sv en el mismo proyecto. La migración puede ser gradual, archivo por archivo.

⚡ Combinacional vs Secuencial

En C, x = y ocurre en un instante. En SystemVerilog hay dos tipos de asignación con semántica completamente distinta — = para combinacional ("x es siempre y") y <= para secuencial ("en el flanco de clock, capturá y en x"). Esto no tiene equivalente en software.

§ 02 Fundamento

El sistema de tipos

logic reemplaza a reg y wire

En Verilog clásico, la distinción wire / reg confunde porque "reg" suena a registro físico, pero un reg puede ser combinacional. La diferencia real es solo dónde podés asignar.

SystemVerilog elimina esta distinción: usá logic siempre. El sintetizador determina si es combinacional o secuencial según cómo lo asignes.

Verilog
wire [31:0] suma_v;
reg  [31:0] contador_v;

assign suma_v = a + b;
always @(posedge clk)
    contador_v <= contador_v + 1;
SystemVerilog
logic [31:0] suma_sv;
logic [31:0] contador_sv;

assign suma_sv = a + b;
always_ff @(posedge clk)
    contador_sv <= contador_sv + 1;

Compuestos: packed vs unpacked

// Packed: bits contiguos, sintetizable como vector único
logic [3:0][7:0] packed_arr;     // 32 bits totales
packed_arr[2] = 8'hFF;           // accede al byte 2 (bits [23:16])

// Unpacked: array de elementos independientes (memoria)
logic [7:0] unpacked_arr [4];    // 4 elementos de 8 bits, modela una memoria
unpacked_arr[2] = 8'hFF;
§ 03 Procedural

Bloques procedurales

Verilog clásico tiene un solo tipo de bloque procedural: always. Su comportamiento depende totalmente de la sensitivity list, lo que es propenso a errores.

// Verilog: ¿es combinacional o secuencial? Hay que leer la sensitivity list.
always @(posedge clk) reg_data <= i_data;       // Secuencial
always @(*) o_result = a + b;                   // Combinacional
always @(a) o_result = a + b;                   // BUG: olvida `b`, latch inferido

SystemVerilog introduce tres bloques especializados que documentan intención y son verificados por el compilador:

always_ff — registros

always_ff @(posedge clk) begin
    if (reset) reg_data <= '0;
    else       reg_data <= i_data;
end

El compilador verifica que solo uses <= (no-bloqueante).

always_comb — lógica combinacional

always_comb begin
    case (op)
        ADD: o_result = a + b;
        SUB: o_result = a - b;
        default: o_result = '0;
    endcase
end

El compilador automáticamente:

  • Construye la sensitivity list (no podés olvidar una señal).
  • Verifica que toda asignación use = (bloqueante).
  • Detecta y reporta latches inferidos como error.
  • Detecta multidrive: dos always_comb asignando la misma señal → error.
⚠ Por qué importa

Si en un forwardingUnit alguien edita el código y olvida el else, Verilog compila silenciosamente e infiere un latch. SystemVerilog con always_comb reporta error de compilación. Bug atrapado antes de simular.

§ 04 Composición

Structs packed

Un struct packed es como un struct de C, pero con la garantía de que los campos están contiguos en bits (sin padding). El sintetizador lo trata como un único vector de N bits.

El problema: 22 señales para mover datos

Un buffer de pipeline tradicional recibe 22 señales separadas. Cada señal aparece en seis lugares: input port, output port, declaración interna, asignación de reset, asignación normal, y assign de salida. Total: 132 líneas para mover 22 valores entre dos etapas.

La solución: agruparlos en un struct

typedef struct packed {
    logic [31:0] PC_inc;
    logic [31:0] A;
    logic [31:0] B;
    alu_op_t     ALUOp;
    branch_t     branch;
    // ... 18 campos más
} id_ex_t;

Ahora el buffer entero se reduce a:

module id_ex_buffer (
    input  logic   i_clk, i_reset, i_enable,
    input  id_ex_t i_data,
    output id_ex_t o_data
);
    id_ex_t buf_reg;

    always_ff @(posedge i_clk) begin
        if (i_reset)       buf_reg <= '0;
        else if (i_enable) buf_reg <= i_data;
    end

    assign o_data = buf_reg;
endmodule

§ 05 Tipado fuerte

Enums tipados

El problema en Verilog

En Verilog se definen los estados de FSM como localparam:

localparam [1:0] RECEIVE_BYTE    = 2'b00;
localparam [1:0] SEND_INFO       = 2'b01;

localparam [1:0] IDLE                = 2'b00;  // ← mismo valor que RECEIVE_BYTE
localparam [1:0] RECEIVE_INSTRUCTION = 2'b01;  // ← mismo valor que SEND_INFO

Si por accidente usás IDLE en lugar de RECEIVE_BYTE, el código compila y funciona aparentemente, pero la lógica está mal.

La solución

typedef enum logic [1:0] {
    ST_RECEIVE_BYTE    = 2'b00,
    ST_SEND_INFO       = 2'b01,
    ST_RECEIVE_COMMAND = 2'b10
} global_state_t;

typedef enum logic [1:0] {
    ST_IDLE                = 2'b00,
    ST_RECEIVE_INSTRUCTION = 2'b01,
    ST_WRITE_MEM           = 2'b10
} recv_state_t;

global_state_t state_global;
recv_state_t   state_recv;

state_global = ST_IDLE;  // ERROR de compilación: tipo incompatible

El compilador rechaza mezclar enums de tipos distintos, aun cuando los valores coincidan numéricamente.

En el waveform viewer (Vivado, GTKWave), las señales tipo enum muestran el nombre del estado en lugar de un valor binario. Reducís errores de lectura.

§ 06 Modularidad

Packages: el equivalente a headers de C

Un package es una unidad compilable separada que puede contener typedef (incluyendo enums y structs), localparam y parameter, function y task.

// mips_pkg.sv
package mips_pkg;
    localparam int NB_REG = 5;

    typedef enum logic [5:0] {
        OP_R_TYPE = 6'b000000,
        OP_LW     = 6'b100011
    } opcode_t;

    typedef struct packed {
        logic [31:0] A, B;
        opcode_t     opcode;
    } id_ex_t;
endpackage : mips_pkg

Cada módulo importa solo lo que necesita:

// Opción 1: importar todo
import mips_pkg::*;

module control_unit (
    input opcode_t i_opcode,
    output ...
);
endmodule

// Opción 2: importar específico (recomendado)
module control_unit
    import mips_pkg::opcode_t;
(
    input opcode_t i_opcode
);
endmodule

§ 07 Abstracción

Interfaces y modports

Las interfaces son una construcción nueva sin equivalente directo en C. Permiten agrupar señales relacionadas y los puertos por los que pasan entre módulos.

Sin interface
module producer (
    output logic        valid,
    output logic [31:0] data,
    input  logic        ready
);
endmodule

module consumer (
    input  logic        valid,
    input  logic [31:0] data,
    output logic        ready
);
endmodule

// Top: tres wires por conexión
module top;
    logic v;
    logic [31:0] d;
    logic r;
    producer p (.valid(v),.data(d),.ready(r));
    consumer c (.valid(v),.data(d),.ready(r));
endmodule
Con interface
interface valid_ready_if;
    logic        valid;
    logic [31:0] data;
    logic        ready;

    modport producer (
        output valid, output data,
        input  ready);
    modport consumer (
        input  valid, input  data,
        output ready);
endinterface

module producer (valid_ready_if.producer ifc);
endmodule

module top;
    valid_ready_if vr_if();
    producer p (vr_if.producer);
    consumer c (vr_if.consumer);
endmodule

Cuándo usar interfaces

  • ✓ Buses con muchas señales (AXI, Wishbone, AHB).
  • ✓ Conexiones que se replican en muchos lugares.
  • ✗ Conexiones simples entre dos módulos — un struct es suficiente.
  • ✗ Si tu equipo no domina la sintaxis de modport.
§ 08 Encapsulación

Funciones y tasks

Igual que en C, podés encapsular lógica en funciones:

function automatic logic [31:0] add_signed(
    input logic [31:0] a,
    input logic [31:0] b
);
    return $signed(a) + $signed(b);
endfunction

// Uso:
assign result = add_signed(op_a, op_b);

Reglas para funciones sintetizables

  • Solo lógica combinacional — sin always_ff adentro.
  • Sin delays (#5).
  • Sin tasks adentro.
  • automatic permite recursión y reentrancia — ponelo siempre.

Caso de uso: ALU como función en package

// En mips_pkg.sv
function automatic logic [31:0] alu_compute(
    input logic [31:0] a, b,
    input logic [4:0]  shamt,
    input funct_t      funct
);
    case (funct)
        FUNCT_ADD:  return $signed(a) + $signed(b);
        FUNCT_ADDU: return a + b;
        FUNCT_SUBU: return a - b;
        FUNCT_AND:  return a & b;
        FUNCT_OR:   return a | b;
        default:    return '0;
    endcase
endfunction

Cualquier módulo que importe el package puede llamar a alu_compute(...).

§ 09 Sintaxis

Operadores y construcciones nuevas

Operador inside

Reemplaza largas cadenas de OR:

Verilog
if (opcode == LW || opcode == LH ||
    opcode == LB || opcode == LWU ||
    opcode == LHU || opcode == LBU)
    ...
SystemVerilog
if (opcode inside {OP_LW, OP_LH,
                  OP_LB, OP_LWU,
                  OP_LHU, OP_LBU})
    ...

Literales '0, '1, 'x

Asignaciones de "todos los bits" sin importar el ancho:

logic [31:0] reg_a;
logic [7:0]  reg_b;

reg_a <= '0;   // 32 ceros
reg_b <= '0;   // 8 ceros — el ancho se resuelve automáticamente
reg_a <= '1;   // 32 unos
reg_a <= 'x;   // 32 X (debug)

Operadores lógicos vs bitwise

SystemVerilog es más estricto: usá &&, ||, ! para expresiones lógicas (resultado 1 bit) y &, |, ~ para operaciones bitwise sobre vectores.

Streaming operators

Reordenar bits de un vector — útil para serialización en UART:

logic [7:0] x = 8'b10110010;
logic [7:0] reversed = {<<{x}};   // 8'b01001101
§ 10 Control de flujo

Case: unique y priority

En Verilog, un case no avisa si faltan casos o hay solapamientos. SystemVerilog agrega dos modificadores que comunican intención y permiten verificación.

unique case

Le dice al sintetizador y al simulador que los casos son mutuamente excluyentes y que al menos uno matchea (o se requiere default):

unique case (opcode)
    OP_LW: ...;
    OP_LH: ...;
    OP_SW: ...;
    default: ...;
endcase
  • En simulación: si dos casos matchean, error en runtime.
  • En síntesis: el sintetizador puede optimizar más agresivamente.

priority case

Especifica que los casos se evalúan en orden y solo el primer match cuenta. Equivale a if/else if/else:

priority case (1'b1)
    irq_high:   handler = HIGH;
    irq_med:    handler = MED;
    irq_low:    handler = LOW;
    default:    handler = NONE;
endcase

Aplicación: control unit con defaults

Verilog — 416 líneas
SW : begin
    o_regDst = 1'b0;
    o_ALUOp = 2'b00;
    o_ALUSrc = 1'b1;
    o_branch = 2'b00;
    o_memRead = 1'b0;
    o_memWrite = 1'b1;
    // ... 13 señales por caso
end
SV — ~160 líneas
always_comb begin
    // defaults arriba
    o_regDst = 1'b0;
    o_ALUOp = ALU_OP_LOADSTORE;
    // ... resto de defaults

    unique case (i_opcode)
        OP_SW: begin
            o_ALUSrc = 1'b1;
            o_memWrite = 1'b1;
        end
        // solo lo que difiere
    endcase
end
§ 11 Replicación

Generate: replicación de hardware

generate permite replicar o parametrizar hardware en tiempo de compilación.

genvar i;
generate
    for (i = 0; i < N; i++) begin : gen_adders
        adder u_add (
            .a (a_vec[i]),
            .b (b_vec[i]),
            .y (y_vec[i])
        );
    end
endgenerate

gen_adders es un nombre jerárquico para acceder a las instancias generadas: top.gen_adders[3].u_add.y.

Caso de uso: inicialización de register file

// En mips_pkg.sv
localparam logic [31:0] REG_INIT [N_REGS] = '{
    32'd0, 32'd15, 32'd40, 32'd2, 32'd1,
    default: 32'd0
};

// En register_file.sv
always_ff @(posedge clk) begin
    if (reset) begin
        for (int i = 0; i < N_REGS; i++)
            r_regs[i] <= REG_INIT[i];
    end
end
§ 12 Genericidad

Parámetros y constantes

Igual que Verilog-2001, los parámetros funcionan así:

module fifo #(
    parameter int DEPTH = 16,
    parameter int WIDTH = 32
) (
    ...
);
    logic [WIDTH-1:0] mem [DEPTH];
endmodule

// Instanciación:
fifo #(.DEPTH(64), .WIDTH(8)) u_fifo (...);

Type parameters — la joya de SV

Podés parametrizar el tipo además del valor:

module flop #(
    parameter type T = logic [31:0]
) (
    input  logic clk,
    input  T     d,
    output T     q
);
    always_ff @(posedge clk) q <= d;
endmodule

// Instanciación con tipo:
flop #(.T(id_ex_t)) u_id_ex_buf (.clk(clk), .d(in_data), .q(out_data));
★ Idea clave

Esto te permite escribir un único módulo de buffer reusable para los cuatro buffers del pipeline. De 367 líneas en 4 archivos a ~15 líneas en 1.

§ 13 Verificación

Assertions: verificación embebida

Las assertions son afirmaciones sobre el comportamiento del diseño que el simulador verifica en cada ciclo. Son ignoradas por el sintetizador, así que no agregan hardware.

Immediate (inline)

always_ff @(posedge clk) begin
    if (regWrite && dest_reg == 5'd0)
        assert (returnPC == RET_NONE)
            else $error("Escritura sobre r0 sin link");
end

Concurrent (más potentes)

property no_write_r0;
    @(posedge clk) disable iff (reset)
    !(regWrite && dest_reg == 5'd0 && returnPC == RET_NONE);
endproperty

a_no_write_r0: assert property (no_write_r0)
    else $error("r0 escrito");

Operadores temporales

// |->: implicación en el mismo ciclo
property req_grant;
    @(posedge clk) req |-> grant;
endproperty

// |=>: implicación en el siguiente ciclo
property stall_then_bubble;
    @(posedge clk) stall |=> !regWrite_in_EX;
endproperty

// ##N: después de N ciclos
property completion;
    @(posedge clk) start |-> ##5 done;
endproperty
✓ Estrategia

Cada vez que arregles un bug, agregá una assertion que lo detectaría. Con el tiempo, el set de assertions se vuelve una red de seguridad muy efectiva.

§ 14 Roadmap

Estrategia de migración paso a paso

No migres todo de golpe. SystemVerilog es superset de Verilog, así que podés hacerlo gradual.

Fase 1 — Cambios mecánicos
1 díaRiesgo: bajo

Renombrá .v a .sv. Reemplazá reg/wire por logic. Cambiá always @(*) por always_comb y always @(posedge clk) por always_ff. Compilá: el compilador reporta los bugs latentes (latches inferidos, mezcla bloqueante/no-bloqueante).

Fase 2 — Centralización de tipos
1-2 díasRiesgo: bajo

Creá mips_pkg.sv con todos los opcodes, funct codes y constantes. Reemplazá los localparam dispersos por imports del package. Convertí los localparam de FSMs en enum tipados.

Fase 3 — Structs en buffers de pipeline
2-3 díasRiesgo: medio

Definí un struct por cada buffer (if_id_t, id_ex_t, etc.) en el package. Reescribí los cuatro buffers usando structs (cada uno baja de ~150 a ~15 líneas). Modificá las etapas adyacentes para producir/consumir el struct entero. Tener buena suite de tests es crítico.

Fase 4 — Refactor de control unit
1 díaRiesgo: bajo

Convertí el case gigante en always_comb + defaults + unique case. Verificá con tests que las salidas son idénticas.

Fase 5 — Refactor de FSM debug
1-2 díasRiesgo: bajo

Convertí localparam de estados en enum. Convertí el always @(posedge clk) monolítico en always_ff + always_comb separados (current/next state).

Fase 6 — Assertions
continuoBeneficio creciente

Cada vez que arregles un bug, agregá una assertion que lo detectaría. La cobertura crece con el tiempo y se vuelve una red de seguridad efectiva.

Fase 7 — Interfaces (opcional)
1 semanaSolo si hace falta

Solo si tu pipeline crece y los structs ya no alcanzan. La curva de aprendizaje de interface/modport es la más alta de SV.

§ 15 Estilo

Buenas prácticas

Convenciones de nomenclatura

// Tipos: snake_case con sufijo _t
typedef enum { A, B } state_t;
typedef struct packed { ... } packet_t;

// Constantes: UPPER_SNAKE
localparam int FIFO_DEPTH = 16;
localparam logic [3:0] CMD_READ = 4'h0;

// Señales: snake_case
logic [31:0] data_in;

// Puertos: prefijo i_ / o_
input  logic i_clk;
output logic o_done;

// Instancias: prefijo u_
adder u_main_adder (...);

// Generate: prefijo gen_
for (genvar i = 0; ...) begin : gen_adders ... end

FSMs: separar estado y lógica

typedef enum logic [1:0] { S_IDLE, S_RUN, S_DONE } state_t;
state_t state, state_next;

// Solo flop del estado
always_ff @(posedge clk) begin
    if (reset) state <= S_IDLE;
    else       state <= state_next;
end

// Lógica de transición
always_comb begin
    state_next = state;     // default: retener
    unique case (state)
        S_IDLE:  if (start) state_next = S_RUN;
        S_RUN:   if (done)  state_next = S_DONE;
        S_DONE:               state_next = S_IDLE;
    endcase
end

// Outputs (Moore: dependen solo del estado)
always_comb begin
    o_busy = (state == S_RUN);
    o_done = (state == S_DONE);
end

Reutilización con type parameters

Un único pipeline_buffer reusable para los 4 buffers:

module pipeline_buffer #(
    parameter type T = logic [31:0]
) (
    input  logic i_clk, i_reset, i_enable,
    input  T     i_data,
    output T     o_data
);
    T buf_reg;
    always_ff @(posedge i_clk) begin
        if (i_reset)       buf_reg <= '0;
        else if (i_enable) buf_reg <= i_data;
    end
    assign o_data = buf_reg;
endmodule

// Uso (un solo módulo para los 4 buffers):
pipeline_buffer #(.T(if_id_t))  u_if_id  (.*);
pipeline_buffer #(.T(id_ex_t))  u_id_ex  (.*);
pipeline_buffer #(.T(ex_mem_t)) u_ex_mem (.*);
pipeline_buffer #(.T(mem_wb_t)) u_mem_wb (.*);

§ 16 Anti-patrones

Errores comunes

1
Mezclar bloqueante y no-bloqueante

Dentro de always_ff usá siempre <=; dentro de always_comb usá siempre =. El compilador lo verifica.

2
Olvidar default en case combinacional

Sin default y sin asignación previa, se infiere un latch. Solución: asignar defaults antes del case. always_comb te avisa.

3
Asignación cruzada entre always_ff y always_comb

Una señal solo puede ser driveada por un bloque (o un solo assign). Si dos bloques asignan la misma señal, error.

4
Anchos incompatibles

Verilog trunca silenciosamente. SV emite warning estricto. Usá a = b[7:0] o cast explícito a = 8'(b) para dejar la intención clara.

5
Usar == con valores que pueden ser X

Si valid = 1'bx, la condición valid == 1'b1 es indeterminada. Para constantes usá === que compara incluyendo X y Z. En RTL, if (valid) directamente.

6
Estados de FSM con valores iguales

Si dos enums distintos tienen el mismo valor numérico, el compilador los rechaza al asignar uno a otro. Esto es bueno: te salva de mezclar FSMs.

7
Inferir un latch cuando querías un cable

if (enable) o = a; sin else infiere latch. always_comb reporta error de compilación.

8
Recargar parameter con tipo erróneo

Usá localparam para constantes derivadas dentro del módulo. parameter es para lo que se sobreescribe al instanciar.

9
Confundir parameter type con parameter int

flop #(.T(32)) da error: 32 no es un tipo. Lo correcto: flop #(.T(logic [31:0])).

10
Asumir que packages funcionan como #include

No se incluyen, se importan como namespaces. Cambiar el package recompila todos los archivos que lo importan. No hay protección contra ciclos: package A no puede importar B si B importa A.
